TASK:
Review every proposal above. Return one entry per proposal, in the same order.

Score each 0 to 5, where 0 is "not true at all" and 5 is "strongly true":
- feasibility: could this be built and operated with today's technology and the data this process
  actually has? Penalise anything needing data nobody said exists.
- evidence_strength: do the cited claims actually support it? Judge the citations, not the prose.
  A proposal citing nothing scores 0. A proposal citing an UNVERIFIED claim as though it were
  established scores at most 2. A proposal citing corroborated, credible claims that genuinely
  support the specific assertion scores 4 or 5.
- business_impact: would this materially change the process's cost, speed or quality?
- risk_level: HIGHER IS WORSE. 5 means this could harm candidates, breach a regulation, or fail in
  a way nobody would notice. Consider what happens when the model is confidently wrong.
- implementation_effort: HIGHER IS MORE WORK. Consider integration, data preparation, change
  management and evaluation, not just the model.

Then give a verdict:
- STRONG: well evidenced, feasible, worth doing first
- SOUND: a good idea with ordinary delivery risk
- QUALIFIED: worth doing only with the conditions you name in your critique
- WEAK: the reasoning or the evidence does not hold up
- REJECTED: should not be attempted as described

Rules:
1. "critique" must state your actual objection in one or two sentences. If you have no objection,
   say what would have to be true for this to work, rather than praising it.
2. Do not be uniformly positive. If every proposal scores 4 or 5 you have not reviewed anything.
   If a proposal is genuinely good, say so and say why it survived scrutiny.
3. Copy "opportunity" as the exact description text of the proposal you are reviewing, so your
   review can be matched to it.

Return STRICT JSON ONLY, no markdown fences, no commentary:
